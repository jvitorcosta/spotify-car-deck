# Genre badge: design

Date: 2026-10-08. Status: approved in brainstorming (sections 1–2, colour preview), awaiting
written-spec review.

## Goal

Show the artist's music genre as a Gen-3 style badge before the artist name in the info box,
like the Pokemon type badge in the status box: `[R&B] D'Angelo`, `[FUNK BR] MC PH`.

## Source (feasibility checked 2026-10-08)

- **Spotify:** artist objects no longer carry `genres` for this app (search and
  `/v1/artists/{id}` both return no field). Not usable.
- **Apple iTunes Search API, artist search** (chosen): no key;
  `https://itunes.apple.com/search?term=<artist>&entity=musicArtist&limit=1&country=BR`.
  ~280-byte JSON with `primaryGenreId` / `primaryGenreName`. Matched 14/14 test artists
  (Gloria Groove Pop, D'Angelo R&B/soul, MC PH Brasileira, Mr.Kitty Eletrônica, Omega Tribe
  J-pop, Metallica Metal, BTS K-pop, Marília Mendonça Sertanejo, Racionais MC's Hip-Hop/Rap, …).
  Rate limit ~20 calls/min: fine with one call per new artist.
- Rejected: MusicBrainz (community tags, strict 1 req/s, 503s in testing), Deezer (album
  genre only), Last.fm / Musixmatch (API keys), song-level genre (4.7 KB per song, every song).

## Badge

- Info box, artist row: badge at the row start, then the artist name. Same style as the type
  badge (rounded, genre colour fill, darker border = `theme::darken`, white capitals with a
  shadow in the border colour, font 1). Size **58×12** (labels up to 9 letters). The artist
  name's maximum width drops from 172 to 108 px; with no badge it keeps 172 px.
- First artist only (the one shown).
- Labels are ASCII (font 1 has no accented capitals): `FORRO`, `AXE`.

The id → badge table is generated by `tools/gen_genres.py` from Apple's genre tree
(`https://itunes.apple.com/WebObjects/MZStoreServices.woa/ws/genres?id=34&cc=br`): every
top-level genre and all its subgenres map to the row above, with the listed subgenre
overrides (K-pop, Funk, Metal, the Brazilian ones) taking precedence. Output:
`src/ui/genre_data.inc` (sorted `{id, badge}` pairs, ~400 entries, flash only), committed.

## Data path

- **Network step `Genre`** in `netplan`: order Art → Lyrics → **Genre** → Walk → Prefetch;
  memory gate `TLS_NEED` (it is HTTPS). Optional work (paused by `Health` like the others).
- **Cache** (pure, host-tested): last 32 artists, keyed by a 32-bit FNV-1a hash of the artist
  name → badge index (or "none"). A cache hit skips the request. "Apple has no match / no
  genre" is cached as none; network errors are not cached (retried the next time the artist
  plays). No retries within a song.
- **Request:** read the whole ~300-byte body into a fixed 1 KB buffer (truncate beyond);
  a pure parser extracts the first `"primaryGenreId":<int>` (and nothing else is needed).
  No JSON library, no heap. HTTP != 200, timeouts, connect/TLS failures → no badge, not cached.
- **Shared:** `shared::postGenre(gen, badge)` / UI `takeGenre(gen, &badge)` — posted for the
  track generation (same pattern as art; stale generations dropped). On a cache hit the
  network task posts the badge right after the track change, so it appears with the title.
- **UI:** `drawNow` draws the artist row at full width; when a genre arrives the artist row
  is repainted (box fill over the row, badge, name at 108 px). The badge index is remembered
  for full redraws of the same track (back from a status screen).
- Log: `[genre] "D'Angelo": 15 -> R&B` / `[genre] "X": none` / `[genre] "X": error rc=-1`.

## Memory

Cache ~32 × (4 + 1) B; 1 KB read buffer on the network-task stack frame of the request
(10 KB stack, 3.7 KB lowest free seen — the buffer is `static` to stay off the stack);
generated table in flash. No new large RAM buffers.

## Testing

Host tests (test first):
- `genre` parser: real Apple responses (Pop 14, R&B 15, Brasileira 1122); `resultCount:0`
  → none; truncated body / missing key / non-numeric → none.
- Badge mapping: every row's ids map to the right label and colour; a subgenre maps to its
  parent's badge; overrides beat the parent (1229 → FUNK BR not BRASIL, 51 → K-POP not POP);
  unknown id → `???` grey; every label fits 58 px in font 1 (≤ 9 chars × 6 px − 1 ≤ 54).
- Cache: miss / hit, cached none, eviction of the oldest at 33 entries, errors not stored,
  hash of names with accents.
- `netplan`: Genre comes after Lyrics and before Walk; `canRun(Genre)` needs `TLS_NEED`.

On device: a session with `[genre]` log lines; the user checks the badges on screen.

## Non-goals

- Song-level genre; multiple artists; Spotify genres (unavailable); a second source (Deezer).
